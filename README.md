# ✈️ AI Travel Planning System

> **A production-oriented multi-agent AI travel planning system built with Python and LangGraph.**

The AI Travel Planning System uses a **multi-agent architecture** to automatically research and generate a complete travel plan based on a user's requirements.

The system coordinates specialized AI agents for **flight search, hotel search, itinerary planning, and final response generation**, while PostgreSQL provides persistent conversation memory.

The application combines **LLM reasoning, real-time API integrations, persistent state, and an interactive Streamlit interface** into an end-to-end AI application.

---

## 🚀 Features

* ✈️ **Flight Search Agent** — Searches for available flight information using the AviationStack API.
* 🏨 **Hotel Search Agent** — Researches hotel options and travel information using Tavily.
* 🗓️ **Itinerary Planning Agent** — Creates a structured day-by-day travel itinerary.
* 🤖 **Final Response Agent** — Combines the outputs from the specialized agents into a complete travel response.
* 🧠 **Persistent Memory** — Stores conversation state using PostgreSQL and LangGraph's PostgreSQL checkpointing.
* 🌐 **Real-Time API Integration** — Connects external travel and search APIs to retrieve current information.
* 💻 **Streamlit Interface** — Provides a simple interactive web interface for users.
* 🔄 **Multi-Agent Orchestration** — LangGraph manages the flow and coordination between agents.

# 🔄 Agent Workflow

### 1. Flight Search Agent

Receives the user's travel requirements and searches for relevant flight information through the **AviationStack API**.

### 2. Hotel Search Agent

Uses **Tavily** to research relevant hotel and destination information based on the user's requirements.

### 3. Itinerary Planning Agent

Processes the travel information and creates a structured itinerary covering the requested trip duration.

### 4. Final Response Agent

Combines the information generated by the previous agents and produces the final travel plan for the user.

### 5. PostgreSQL Memory

Conversation state is persisted using PostgreSQL, allowing the application to maintain context across interactions.

# 🧠 Multi-Agent Architecture

Instead of relying on a single LLM prompt to perform every task, the application separates responsibilities across specialized agents.

```text
User
 │
 ▼
LangGraph
 │
 ├── Flight Agent
 │
 ├── Hotel Agent
 │
 ├── Itinerary Agent
 │
 └── Final Response Agent
 │
 ▼
Final Answer
```

This architecture makes the workflow more modular and allows individual agents to focus on specific tasks.

# ⚙️ Installation & Setup

## 1. Clone the Repository

```bash
git clone https://github.com/YOUR_USERNAME/ai-travel-planning-system.git
```

```bash
cd ai-travel-planning-system
```

---

## 2. Create a Python Virtual Environment

```bash
python -m venv langgraph_env3
```

Activate the environment.

### Windows

```bash
langgraph_env3\Scripts\activate
```

### macOS / Linux

```bash
source langgraph_env3/bin/activate
```

---

# 3. Install Dependencies

Install the required Python packages:

```bash
pip install langgraph langchain langchain-openai langchain-groq langchain-community langchain-tavily psycopg[binary] psycopg_pool python-dotenv tavily-python requests streamlit
```

Install the PostgreSQL checkpointing dependencies:

```bash
pip install -U "psycopg[binary,pool]" langgraph-checkpoint-postgres
```

---

# 4. Install PostgreSQL

Install PostgreSQL on your local machine.

Create a database for LangGraph memory:

```sql
CREATE DATABASE langgraph_memory_demo;
```

Make sure you remember your:

* PostgreSQL username
* PostgreSQL password
* PostgreSQL port
* Database name

---

# 5. Configure Environment Variables

Create a `.env` file in the root directory.

```env
GROQ_API_KEY=your_groq_api_key
TAVILY_API_KEY=your_tavily_api_key
AVIATIONSTACK_API_KEY=your_aviationstack_api_key

DATABASE_URL=postgresql://postgres:your_password@localhost:5433/langgraph_memory_demo
```

### 🔐 Security

**Never commit your `.env` file or API keys to GitHub.**

Add `.env` to `.gitignore`:

```text
.env
__pycache__/
*.pyc
venv/
.venv/
```

For other developers, provide a `.env.example` file:

```env
GROQ_API_KEY=
TAVILY_API_KEY=
AVIATIONSTACK_API_KEY=
DATABASE_URL=
```

# 📊 Why This Architecture?

A single-agent approach could handle the entire request through one large prompt, but separating responsibilities provides a more modular architecture.

Each agent has a specific responsibility:

```text
Flight Agent
     ↓
Flight Information

Hotel Agent
     ↓
Hotel Information

Itinerary Agent
     ↓
Travel Schedule

Final Agent
     ↓
Unified Response
```

This makes individual components easier to understand, test, modify, and extend.
